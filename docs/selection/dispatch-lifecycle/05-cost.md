# 成本守护: 派单生命周期技术选型
（角色 cost-keeper · 2026-10-22 · lead 代跑）

## 结论三态：**建议采用，成本可忽略**

| 项 | 估算 | 说明 |
|---|---|---|
| 新增代码 | ~200 行 Python（1 模块 + 2 子命令） | 纯 stdlib，零第三方依赖 |
| 新增测试 | 3–5 例 | 与现有 pytest 体系一致 |
| 运行时开销 | 每次 sweep 一次目录遍历 | run 数 ≤ 数十，毫秒级 |
| 外部服务 | **0** | 对比 Temporal/Dagster 要服务端，直接否掉 |
| 维护成本 | 低 | 形状抄 gstack（lease）与 ruflo（projection），不发明新概念 |

## 为什么不引外部编排引擎

| 方案 | 成本 | 结论 |
|---|---|---|
| Temporal / Dagster / LangGraph | 服务端 + 部署 + 运维 + 学习曲线 | 不采用（违反 ADR-0001 文件优先） |
| 自写 seat/sweep/repair | 200 行 + 5 测 | 采用 |

未证实：run 数到 1000 时的遍历耗时（未压测）。
