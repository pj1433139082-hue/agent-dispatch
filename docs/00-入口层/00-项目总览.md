# 项目总览

**派单台 · agent-dispatch** 是一个文件优先的任务编排分发 CLI：把 Markdown 票据变成可执行工单，经过独立验收和异体评审后才允许进入 `done`。当前版本 v0.2，Python 3.11+，运行时只用标准库；v0.2 增加 DSH 看板真实投递与外部结果回写。

## 当前状态

- 业务实现：`src/agent_dispatch/`，70 个测试通过；入口 `dispatch`。
- 启动任务：`tasks/kickoff` 记录项目启动规划事实（payload、plan、方案接受记录），已 `completed_locally`；启动任务不等于业务实现验收。
- 仓库：https://github.com/pj1433139082-hue/agent-dispatch ，默认分支 `main`，MIT，public。
- 门禁：CI job `test` 是 `main` 的必需状态检查；PR 实测会先 `BLOCKED`，检查通过后 `CLEAN`。
- DSH：`dispatch dsh push/status/outcome` 已对本机 50567 看板做过真实创建、回读和外部结果回写探针；探针卡已清理。

## 阅读顺序

1. `README.md` — 问题、对象、快速开始、CLI 一览。
2. `CONTEXT.md` — 票据、Run、工单、回执、验收、评审等术语。
3. `docs/project/architecture.md` — 模块边界与数据流。
4. `docs/project/environment.md` — 实际运行环境、安装、测试与 CI 证据。
5. `docs/project/progress.md` — 已完成、已知边界、下一步候选。
6. `docs/adr/` — 关键架构决策。
7. `tasks/kickoff/plan.md` — v0.1 技术选择、风险与验收方法。

## 边界

v0.2 不做 Web UI、多用户权限、云沙箱、自动合并/部署，也不替代 DSH Agent Teams 或 Codex；它负责“票据 → 工单 → 回执 → 验收 → 评审 → 状态/导出/看板投递”的最小闭环。看板投递不是验收结论。阶段与档位以 `task.json` 和 CLI 查询为准，不从本页或聊天推断。
