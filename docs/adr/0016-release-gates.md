# 发布前三条：评审窗口、变异检查、集成者

三件事都围绕同一句话："签字/落地之前的证据要能被独立复核"。

- **评审窗口**：team 模式下交叉评审最容易变成"边看边改"，所以 `review-window --open/--close` 用 sha256 快照封住窗口；改过就拒绝签字。**选了快照而不是文件锁**——锁要改 teammate 的写权限，跨进程不可靠；快照只读、可复算。
- **变异检查**：`mutate` 把工作树退到 `base_commit` 重跑票面 Verify。全过说明判据不依赖这次改动（`weak`）。**选了"回退跑"而不是 AST 变异**——语言无关、零依赖，先覆盖"判据是否真的在验东西"这一层。
- **集成者**：`integrate` 把多条 land 分支按序合进一条分支并可选跑全量回归，替代人工 merge。**选了"新建分支"而不是直接合 main**——与 land 的边界一致：工具只造分支，PR 仍由人开。

**Considered Options**：文件锁（跨进程不可靠）、AST 变异（要按语言写规则）、直接合 main（破坏 land 的边界）。

**Consequences**：team 签字多一步开/关窗口；mutate 只覆盖"回退后是否失败"，不覆盖"部分回退"；integrate 冲突时整批回滚（不产半成品分支）。
