## 3. 团队模式结论

### 问题：千问办公的 `Agent` 工具能不能当 `spawn_worker` 用？

**能。**

实测过程：
1. `dispatch align demo --level quick` → 生成问卷 `docs/questions/demo.md`（exit 0）
2. `dispatch select demo --mode team` → 生成选择包 `docs/selection/demo/`（含 00-panel.json + 3 角色 brief + 99-summary.md）（exit 0）
3. 用 `Agent` 工具起 3 个独立子会话：
   - 第 1 个（单独）：写 01-oss.md → 成功
   - 第 2、3 个（并行，同一消息块）：分别写 02-sources.md 和 03-adversary.md → 均成功

验证结果：
- 所有 3 个文件以 `Persona: {role}` 开头 ✓
- 文件内容互相隔离，无交叉污染 ✓
- 子 agent 有完整文件系统读写权限 ✓
- 并行调用确实并行执行（时间戳 23:00–23:01 内完成） ✓

### 调用方式

```
Agent(subagent_type="general-purpose", prompt="写文件到 {path}，内容如下...")
```

并行时在同一个 assistant 消息块中放多个 Agent 调用。

### 与 DSH spawn_teammate 的差异

| 特性 | DSH spawn_teammate | QwenWork Agent |
|---|---|---|
| 异步 | ✓（起后可做别的） | ✗（同步等待返回） |
| 并行多个 | ✓ | ✓（同消息块多调用） |
| 中途追问 | ✓（send_message） | ✗（一次性 prompt） |
| 查看状态 | ✓（list_agents） | ✗ |
| 上下文隔离 | ✓（context: "fresh"） | ✓（每个 Agent 独立上下文） |

**结论**：对于 grill/selection 流程（给 brief → 收证据 → 汇总），`Agent` 完全够用。不需要中途追问，因为 brief 已经包含了完整指令。

## 4. 不兼容清单

| # | 步骤 | 问题 | 根因 | 严重度 |
|---|---|---|---|---|
| 1 | `verify` 在 `render` 后直接调用 | 报错 `ticket is claimed, expected running` | 必须先 `dispatch start <id>` 推进状态机。交接文件遗漏了这一步。 | 低（文档补全即可） |
| 2 | harness-adapters.md 工具名 | 写的 `question`/`bash`/`task`，实际是 `AskUserQuestion`/`Bash`/`Agent` | 千问办公的对外 API 名与内部描述不一致。技能正文用能力槽名所以不影响运行，但映射表需要修正。 | 低（不影响功能） |
| 3 | 无 `list_workers`/`message` | 不能中途查看或追问子 agent | QwenWork 架构限制。对 dispatch 流程无影响（brief 已含完整指令），但限制了更复杂的动态协作场景。 | 信息级 |

**没有阻塞性不兼容。** 完整单票流程（T1–T7）和团队模式均可正常运行。
